# `#RRGGBB` colours were emitted transparent

Evidence for [#516](https://github.com/yschimke/compose-preview-server/issues/516).

Both PNGs are the **same design** — `spotify-wear-widget`, a `remote-m3` Large Wear widget —
generated by `WearWidgetCodeExporter`, compiled into `:samples:wear-widget` in
[`yschimke/compose-ai-tools`](https://github.com/yschimke/compose-ai-tools), and rendered through
that module's Android preview lane. The only difference between them is `argbLiteral`.

| File | Emitted | Result |
| --- | --- | --- |
| `before-six-digit-transparent.png` | `Color(0x1DB954)`, `Color(0xFFFFFF)`, `Color(0x121212)` | Blank. Alpha `0x00` on every colour, including the widget's own background. |
| `after-six-digit-opaque.png` | `Color(0xFF1DB954)`, `Color(0xFFFFFFFF)`, `Color(0xFF121212)` | The widget draws. |

The design stores `#1DB954` — six digits, which is the spelling the commit-time validator asks
for. `androidx.compose.ui.graphics.Color` reads its argument as ARGB, so splicing six digits
through leaves the alpha byte zero.

The album artwork is absent from both: a generated widget takes its bitmaps as `RemoteImageBitmap`
parameters, and the generated `@Preview` supplies `ImageBitmap(1, 1)` placeholders. The 52dp gap on
the left of the "after" render is that placeholder occupying its slot.

The "after" render also shows the play button clipped at the right edge and the content top-aligned
rather than centred. That is a **separate** defect — the exporter drops a row's `verticalAlignment`
property, which the canvas does read — tracked in
[#518](https://github.com/yschimke/compose-preview-server/issues/518), not fixed here.
