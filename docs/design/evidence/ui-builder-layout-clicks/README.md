# Clickable state layouts exported as Compose

The semantic design is the [same saved layout](../ui-builder-live-document-preview/sample.document.json)
used by the real RC playback proof. For the ordinary Compose export, only its catalog pin changes to
`m3-catalog` and its title to `Clickable state layout`.

Before this fix, the combined local server accepted the design but hosted MCP returned three
`UNPROVEN_CALL_SITE` diagnostics: `Box` has no `onClick` parameter. The shared projection now maps
layout clicks to `Modifier.clickable`, preserving the authored modifier order. Box, Row and Column
use this mapping; components with their own handlers retain those parameters.

The callback is a typed `ScreenValue.ActionLambda` in the shared generator. It carries the same
ordered state writes and validation as component handlers. The source is not assembled by replacing
strings in generated Kotlin. The released generator floor gives a located refusal until a generator
with the new vocabulary is selected; local staging exercises the change without a release.

[Exact generated Kotlin](../../fixtures/ui-builder/clickable-state-layout.kt.txt) is compiled as test
source by the existing `:ui-builder` JVM target. `GeneratedLayoutClicksTest` clicks through purple,
green, fallback blue, and purple again at densities 1 and 2. It checks that each active clickable
region remains 312 dp wide inside 24 dp padding. The PNGs here are unedited captures from those actual
compiled Compose tests, not browser mockups:

- [Initial branch](first.png)
- [After the first click](second.png)
- [Fallback after the second click](fallback.png)

`LayoutClickExportTest` compares every generated byte with the source the interaction test compiles,
and separately checks Row/Column mapping and modifier order. `ServeUiBuilderMcpIntegrationTest`
creates this design over hosted MCP and checks its export against the same compiled source. The
upstream generator tests cover serialization, action order and invalid callback assignments.

Run after staging `:screen-model` (the helper also stages `:gradle-plugin:preview-discovery`):

```sh
python3 scripts/stage-local-dependency.py --checkout /path/to/compose-ai-tools --module :screen-model --output build/local-dependencies/remote-export
VERIFY_LOCAL_STATE_SELECTION=true VERIFY_LOCAL_LAYOUT_CLICKS=true ./gradlew -PlocalDependencies=build/local-dependencies/remote-export/local-dependencies.properties :server:test --tests '*LayoutClickExportTest' --tests '*ServeUiBuilderMcpIntegrationTest' :ui-builder:jvmTest --tests '*GeneratedLayoutClicksTest'
```

The exact Kotlin fixture compiles and runs on the released consumer dependency floor too. Without
the local generator, export tests check its explicit refusal instead of treating it as success.

This closes layout-click mapping to ordinary Compose. The combined-host probe also found that
plain Remote layout roots fell through to the component-record exporter. The subsequent
[ordinary-root export change](../ui-builder-remote-root-source/README.md) closes that source-export
gap. Broader component and operation coverage, String state, computed/nullable values and
reusable-component fidelity remain required by the overall goal.

## Combined local verification

The full staged run passes 945 editor JVM tests, 46 shared-export tests and 26 targeted server/MCP
checks, plus the runtime ABI check, WASM build and server distribution build. The released floor
passes its targeted export/MCP and compiled-interaction tests and Wasm compilation. Formatting,
project-boundary validation and golden regeneration pass; no existing golden changes.

[Actual existing WASM Code pane](browser-code.png) shows this layout and its generated `when`.
`verify-layout-click-export.mjs` creates a fresh design with the catalog pin returned by hosted MCP,
checks the exported Kotlin against the compiled fixture and validates its digest, then captures the
real editor's Code pane. Source bytes and executable behavior are automated assertions; the painted
Code pane is visually reviewed rather than read as DOM text. The final run has no browser errors.
`verification.json` records its design ID, pin, byte count and digest.

```sh
UI_BUILDER_TEST_TOKEN='<local-token>' CHROME_PATH='/path/to/Chrome' node preview-harness/verify-layout-click-export.mjs http://127.0.0.1:5623
```
